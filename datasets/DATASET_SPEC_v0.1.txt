SETU NER Risk Dataset v0.1

Target geography:
Guwahati -> Imphal corridor

Primary objective:
Predict a disruption proxy for a road/network segment.

Primary target:
disruption_proxy

Data sources:
1. OpenStreetMap / Overpass
2. Open-Meteo historical weather
3. GDACS disaster/event data

Core features:
- segment_id
- timestamp
- latitude
- longitude
- elevation_m
- road_type
- segment_length_km
- precipitation_mm
- wind_speed_kmh
- wind_gust_kmh
- temperature_c
- humidity_pct
- weather_code
- nearby_disaster_count
- nearest_disaster_distance_km
- disaster_type
- disaster_severity
- accessibility_score
- vehicle_type
- disruption_proxy
- label_type
- label_source
- label_derivation_method

Label provenance contract:
- label_type is required and must be one of: observed, derived, synthetic.
- observed means the target label is directly recorded as a real-world operational observation from an identified source; label_source must identify that source and label_derivation_method must be "direct_observation".
- derived means the target label is computed from one or more real/public signals because direct ground-truth labels are unavailable; label_source must identify the input data sources and label_derivation_method must describe the deterministic derivation rule.
- synthetic means the target label is generated for testing, simulation, or augmentation rather than observed from a real event; label_source must identify the generator or simulation source and label_derivation_method must describe the generation rule.
- label_source and label_derivation_method must not be left ambiguous or represented as observed when the label is derived or synthetic.

Important:
disruption_proxy is a derived prototype label, not a claim of observed road closure.
Real observations, derived labels, and synthetic labels must remain distinguishable through the label provenance fields above.

disruption_proxy Contract & Specification:
1. Data Type:
   - Primary evaluation/training target: int (binary classification: 0 or 1).
   - Secondary auxiliary target: float (continuous disruption risk score in [0.0, 1.0]).

2. Valid Value Range:
   - Binary label: {0, 1} where 0 = normal conditions (no disruption proxy triggered) and 1 = disrupted proxy triggered.
   - Continuous score: [0.0, 1.0] where 0.0 = minimal disruption indicator and 1.0 = maximum disruption indicator.

3. Temporal Window:
   - Calendar date window: 00:00:00 to 23:59:59 UTC (matching daily historical weather aggregation and daily incident timestamps).
   - A segment row represents conditions aggregated across that specific 24-hour window.

4. Spatial Window:
   - Segment proximity buffer: road segment midpoint or point-to-segment geometry within a 10.0 km radius (or the incident's explicit impact_radius_km) of a reported GDACS disaster / field hazard centroid.

5. Canonical Deterministic Derivation Rule:
   - Binary disruption_proxy is evaluated deterministically as 1 if ANY of the following hazard threshold conditions are satisfied:
     a) Active disaster proximity: nearest_disaster_distance_km <= 10.0 AND disaster_severity >= 0.50
     b) Severe precipitation: precipitation_mm >= 50.0 (regional flood/landslide risk threshold)
     c) Gale wind hazard: wind_gust_kmh >= 65.0 (obstruction/tree fall hazard threshold)
     d) Fragile infrastructure impact: accessibility_score < 0.40 AND precipitation_mm >= 25.0
     Otherwise, disruption_proxy = 0.
   - Continuous disruption_proxy score is the unweighted/weighted composite index bounded to [0.0, 1.0].

6. Producer / Evaluator Contract:
   - Producers of datasets populated with this target MUST set:
     * label_type = "derived"
     * label_source = "GDACS + Open-Meteo + OSM"
     * label_derivation_method = "deterministic_threshold_rule_v0.1"
   - Evaluators and ML models consuming disruption_proxy MUST treat it exclusively as an engineered proxy signal for decision-support experiments.
   - Never represent or report disruption_proxy as observed physical road closure, police closure confirmation, or ground-truth traffic standstill.
